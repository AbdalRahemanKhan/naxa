API Reference
NAXA v0.3.0 — structured, sourced, auditable signal chain data for AI agents and analysts.
Authentication Endpoints Code examples Response schema
Authentication
All /v1/* endpoints require a Bearer token in the Authorization header. The /health endpoint is unauthenticated.
To generate a key, run this once in your terminal:
python -c "import secrets; print('naxa_live_' + secrets.token_hex(16))"
Then set it as your NAXA_API_KEY environment variable.
# Every authenticated request curl -X POST https://naxa.onrender.com/v1/analyze \ -H "Authorization: Bearer naxa_live_<your_key>" \ -H "Content-Type: application/json" \ -d '{"event":"canal_restriction","date":"2023-08-01"}'

GET/v1/historyBrowse backtested event database
Returns all 14 historical events used in backtesting, with signal summaries and data quality ratings.
GET/v1/history/:event_idFull event record
Returns the complete event record including confounders, source attribution, and all signal moves.
GET/healthNo auth required
Server liveness check. Used by Render health monitor and UptimeRobot.

Guide
New to NAXA? Everything explained — from signal chains to confidence receipts.
⛓
Signal Chain
When a macro event happens — a canal drought, a port blockage — it doesn't affect just one market. It triggers a cascade: first freight rates move, then shipping equities react, then agricultural commodities adjust weeks later. NAXA maps this whole chain from a single event.
Panama drought → freight rates ↑ (day 12) → tanker equities ↑ (day 10) → grain prices ↔ (day 45)
🎯
Confidence Score
A number between 0 and 1 showing how much to trust a signal. Unlike an LLM saying "I'm 70% confident," NAXA confidence scores are calculated from real historical data — how often this exact type of event moved this exact asset in the predicted direction.
Score 0.702 = weighted hit rate (0.6) + magnitude consistency (0.4), penalized for small sample size
📊
Hit Rate
The percentage of historical events where an asset moved in the predicted direction. A hit rate of 1.0 means every comparable historical event moved this way. A hit rate of 0.5 means it's a coin flip — we flag those as low confidence.
Tanker equities: hit_rate 1.0 — all 14 historical disruptions moved tanker stocks upward
🔢
n= (Sample Size)
How many historical events were used to calculate the confidence score. A score based on n=14 is far more trustworthy than n=3. NAXA always shows you the n= so you know exactly how much weight to give the signal. We never hide it.
Current database: n=14 events from 2011–2024. Target: n=20+ for higher confidence ceiling
📐
Severity Index
A 0–1 score for how severe the disruption is. Calculated as: (% capacity reduction) × (duration factor). The Panama Canal drought scored 0.85 — a 30% reduction sustained for 32 weeks. Severity feeds directly into confidence weighting.
Suez blockage 2021: 0.95 (100% blocked, 6 days) · Panama drought 2023: 0.85
🔄
Proxy Data
When the ideal data source isn't freely available, NAXA uses a substitute that measures the same underlying signal. We always flag proxies visibly and explain exactly what was substituted and why. Transparency is the product.
Drewry WCI (paywalled) → FRED PPI Deep Sea Freight as proxy. Same signal, monthly frequency
📅
Lag Days
How many days after an event before the effect typically shows up in market data. Freight rates often move within 2 weeks. Agricultural commodity prices can take 45 days. NAXA specifies the expected lag for every signal — so you know when to look, not just what to look for.
Freight rates: lag 10–14d · Shipping equities: lag 7d · Grain: lag 45d
🧱
Layers (1–4)
NAXA organizes the signal chain into layers by proximity to the event. Layer 1 is the most direct (canal throughput). Layer 2 is freight rates. Layer 3 is equity markets. Layer 4 is downstream commodities. Each layer moves at a different lag and with different confidence.
L1: Canal ops → L2: Freight rates → L3: Equities → L4: Agricultural prices
🏦
Backtesting
Running a model against historical data to see how it would have performed. NAXA backtests every signal against all comparable historical events in its database. This is the fundamental difference from LLM-generated confidence — backtested numbers have receipts.
14 events from 2011–2024 backtested. Every confidence score cites its n=, hit_rate, date range
Frequently Asked Questions
Why does NAXA show "BELOW EXPECTED" on some signals? +
When a signal's measured 30-day move falls outside the historically expected range, NAXA flags it "BELOW EXPECTED" rather than hiding it. This is intentional — it tells you the historical pattern broke down for this event, possibly due to confounders like macroeconomic conditions or data lag. Honesty about failure is more valuable than silence about it.
What does "THIN BACKTEST" mean? +
It means the confidence score is based on fewer than 6 comparable historical events. The signal may still be directionally correct, but the statistical confidence is weaker. We show it so you can decide how much weight to give it. As the NAXA database grows, thin backtests will strengthen automatically.
Why does NAXA not predict prices? +
NAXA maps signal chains — it shows what typically moves, in which direction, with what lag, based on historical patterns. It does not predict exact price levels. Price prediction requires a different class of model and introduces a different kind of liability. NAXA's job is to compress the research workflow, not replace analyst judgment on position sizing.
How is NAXA different from Bloomberg? +
Bloomberg provides tier-1 market data — prices, fundamentals, news. NAXA provides alternative data signal chains. They're complementary. A boutique fund analyst using Bloomberg for price data can use NAXA to instantly map what downstream effects to look for after a macro event — without spending 20 minutes manually building the chain themselves.
Can AI agents use NAXA directly? +
Yes — that's the primary design intent. NAXA returns structured JSON with a machine_readable_chain field specifically built for agent consumption. Every response serves both humans (the analyst dashboard) and agents (the JSON payload) from the same API call. See the API tab for integration examples.
